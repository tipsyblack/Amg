# Запуск на выделенном сервере (Ubuntu/Debian)

Инструкция простым языком: как поставить проект на сервер и генерировать
ролики оттуда, не занимая свой компьютер.

## Что понадобится

- Выделенный сервер с Ubuntu или Debian и доступом по SSH.
- Ключи: OpenRouter (сценарий + картинки) и ElevenLabs (озвучка).
- Примерно 3 ГБ свободного места (Node.js, зависимости, headless Chrome).

## Шаг 1. Подключиться к серверу

**Где взять данные для входа.** Пользователь (обычно `root`), IP-адрес и
пароль хостинг присылает письмом при покупке сервера, и они же лежат в панели
управления хостингом. Никому их не пересылайте — ни в переписке, ни в чате с
ботом.

**Самый простой способ — вообще без SSH-клиента.** У большинства хостингов в
панели управления есть кнопка «Консоль» (VNC, «веб-консоль», «терминал»). Она
открывает то же самое прямо в браузере: ничего ставить не нужно, вводите логин
и пароль и работаете. Если такая кнопка есть — используйте её.

**Windows.** Откройте «Терминал» или PowerShell (кнопка «Пуск», начните
набирать «терминал») и введите:

```bash
ssh root@айпи-сервера
```

SSH встроен в Windows 10 и 11, ставить ничего не нужно. Если команда не
находится — поставьте [PuTTY](https://www.putty.org/): в поле Host Name
впишите IP, нажмите Open.

**macOS.** Откройте «Терминал» (Cmd+Пробел, наберите «терминал») и введите ту
же команду.

**С телефона.** Подойдёт приложение Termius (есть на iOS и Android): New Host
→ вписать IP, имя пользователя и пароль → Connect.

При первом подключении спросят `Are you sure you want to continue connecting?`
— ответьте `yes`. Затем попросят пароль: **при вводе на экране ничего не
появляется**, ни точек, ни звёздочек. Это нормально, просто наберите вслепую и
нажмите Enter. Пароль удобнее вставить из буфера: в Windows — правой кнопкой
мыши, на Mac — Cmd+V.

Получилось, если в строке появилось что-то вроде `root@server:~#`.

## Шаг 2. Скачать проект

Репозиторий публичный, поэтому никакие токены и ключи для этого не нужны:

```bash
git clone https://github.com/tipsyblack/Amg.git
cd Amg
```

Если нужная ветка не открылась сама:

```bash
git checkout claude/remotion-video-automation-biby8g
```

## Шаг 3. Установить всё одной командой

```bash
sudo bash scripts/setup-server.sh
```

Скрипт сам поставит Node.js 22, зависимости проекта и системные библиотеки,
без которых Remotion не сможет рендерить видео. Занимает несколько минут.

## Шаг 4. Вписать ключи

Ключи можно задавать **из чата с ботом** (`/setkey`), и ради этого всё и
затевалось. Но одну строку придётся вписать здесь руками — ту, что говорит
боту, чей он:

```
TELEGRAM_ALLOWED_CHAT_ID=ваш_chat_id
```

Ваш chat id бот покажет сам: напишите ему `/keys`, и он назовёт число в ответе.
Пока эта строка пуста, бот отвечает любому, кто его найдёт, и правка ключей из
чата была бы дырой — поэтому она и выключена до тех пор.

После этого перезапустите бота (`systemctl restart amg-bot`) — и дальше
остальные ключи задаются командой `/setkey ИМЯ значение` прямо в Telegram, без
возвращения сюда.

Скрипт уже создал файл `.env`. Откройте его и заполните:

```bash
nano .env
```

Заполнить нужно две строки:

```
OPENROUTER_API_KEY=ваш_ключ_openrouter
KIE_API_KEY=ваш_ключ_kie
```

Сохранить в nano: `Ctrl+O`, `Enter`, затем `Ctrl+X`.

Где брать:

- **OPENROUTER_API_KEY** — openrouter.ai/keys (генерация сценария).
- **KIE_API_KEY** — kie.ai, раздел с API-ключами. Один ключ покрывает и
  озвучку (модели ElevenLabs), и генерацию картинок — отдельный аккаунт
  ElevenLabs не нужен.

Остальные настройки в `.env` уже заполнены значениями по умолчанию и обычно
менять их не требуется. Полезная — `KIE_TTS_VOICE` (голос озвучки): по
умолчанию `Rachel`, список доступных голосов смотрите в кабинете Kie.ai.
Для русского языка выбирайте голос с поддержкой multilingual.

Файл `.env` в git не попадает (он в `.gitignore`), так что ключи не утекут
в публичный репозиторий. Но на самом сервере это обычный файл — держите
доступ к серверу закрытым.

## Шаг 5. Сгенерировать ролик

```bash
npm run generate -- "бриф: что за продукт, для кого, какой посыл"
npm run render
```

Первая команда напишет сценарий, озвучит его и нарисует картинки к сценам.
Вторая — соберёт из этого видео. Готовый файл: `out/video.mp4`.

При первом рендере Remotion докачает headless Chrome (~150 МБ) — это
нормально, происходит один раз.

## Шаг 6. Забрать видео с сервера

С **вашего** компьютера (не с сервера):

```bash
scp пользователь@айпи-сервера:~/Amg/out/video.mp4 .
```

Файл окажется в текущей папке на вашем компьютере.

## Если что-то пошло не так

**`npm run generate` падает с ошибкой 401 или 403**
Ключ неверный или закончились деньги на балансе. Проверьте ключи в `.env` и
баланс в кабинете OpenRouter / Kie.ai.

**Ошибка «Kie.ai не смог выполнить задачу»**
В сообщении будет причина от самого сервиса. Частые случаи: закончились
кредиты, модель в `KIE_TTS_MODEL` / `KIE_IMAGE_MODEL` переименована или
недоступна (сверьтесь со списком моделей в кабинете Kie.ai), либо промпт
отклонён фильтрами.

**Ошибка «Kie.ai не ответил за 600 с»**
Задача слишком долгая или зависла. Увеличьте лимит в `.env`:
`KIE_TIMEOUT_SECONDS=1200`.

**Картинки генерируются, но персонаж не похож на Шамиля**
Проверьте, что ссылка на эталон доступна: откройте в браузере значение
`CHARACTER_REFERENCE_URL` (или ссылку по умолчанию из
`src/pipeline/config.ts`) — должна открыться картинка с персонажем. Если
репозиторий стал приватным, ссылка перестанет работать: выложите картинку
в любое публичное место и впишите её адрес в `CHARACTER_REFERENCE_URL`.

**Рендер падает с ошибкой про библиотеки или Chrome**
Скорее всего не хватает системной библиотеки. Запустите скрипт установки
ещё раз: `sudo bash scripts/setup-server.sh`.

**Рендер падает из-за нехватки памяти**
Уменьшите параллельность рендера:

```bash
npx remotion render src/remotion/index.ts VideoComposition out/video.mp4 \
  --props=data/video-data.json --concurrency=1
```

**Хочется обновить проект вручную**

```bash
cd ~/Amg
bash scripts/auto-deploy.sh
```

Или настроить автоматическое обновление — см. следующий раздел.

## Автодеплой: обновления с GitHub сами приезжают на сервер

Скрипт `scripts/auto-deploy.sh` проверяет, появились ли новые коммиты в
GitHub, и если да — обновляет код на сервере. Зависимости (`npm ci`)
переустанавливает только когда реально менялся `package-lock.json`, чтобы не
тратить время впустую.

Важно: скрипт **только обновляет код**. Он ничего не генерирует и не
рендерит — деньги на API сами по себе тратиться не начнут.

### Проверить вручную

```bash
cd ~/Amg
bash scripts/auto-deploy.sh
```

Если обновлений нет — скрипт молча завершится. Если есть — покажет, что
обновил.

### Включить автоматический запуск

Добавьте задание в cron (проверка каждые 5 минут):

```bash
crontab -e
```

Если редактор спросит, какой использовать — выбирайте `nano`. Впишите одну
строку (замените `/root/Amg` на реальный путь, если клонировали в другое
место):

```
*/5 * * * * /bin/bash /root/Amg/scripts/auto-deploy.sh >> /root/Amg/deploy.log 2>&1
```

Сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.

Проверить, что задание добавилось:

```bash
crontab -l
```

Посмотреть, что происходило:

```bash
tail -20 ~/Amg/deploy.log
```

### Что нужно знать про автодеплой

- **Ваши ключи не пострадают.** Обновление приводит к состоянию GitHub
  только те файлы, что лежат в репозитории. Файл `.env`, папки `out/`,
  `public/audio/`, `public/images/` не затрагиваются — это проверено.
- **Локальные правки кода на сервере будут перезаписаны.** Если вы
  отредактируете, например, `src/remotion/Scene.tsx` прямо на сервере,
  следующий автодеплой заменит его версией из GitHub. Правьте код через
  GitHub, а сервер держите как «приёмник».
- **Два деплоя одновременно не пойдут** — скрипт защищён блокировкой.
- **Не запускайте деплой посреди генерации.** Если `npm ci` начнётся во
  время `npm run generate`, генерация может сломаться. Вероятность мала
  (обновления зависимостей редки), но если хотите исключить полностью —
  временно отключите cron перед долгим прогоном:
  `crontab -r` уберёт задания, потом добавите заново.

### Отключить автодеплой

```bash
crontab -e     # удалить строку и сохранить
```

### Почему именно так, а не через GitHub Actions

Есть вариант «по push из GitHub сразу лезть на сервер по SSH». Он быстрее
реагирует, но требует положить приватный SSH-ключ от сервера в настройки
GitHub — то есть доверить доступ к серверу внешнему сервису. Вариант с cron
ничего наружу не открывает и никаких секретов на GitHub не хранит: сервер
сам ходит за обновлениями. Для одного сервера и неспешной задачи это
надёжнее и проще. Если понадобится мгновенная реакция на push — можно
переделать.

## Про автоматический запуск по расписанию

Пока сознательно не настроено: сначала стоит убедиться, что стиль роликов
вас устраивает. Автогенерация без присмотра тратит деньги на API-запросы
при каждом запуске. Когда результат станет предсказуемым — добавим
cron-задание.
