# Телеграм-бот: генерация роликов из чата

Бот ведёт по шагам: бриф → референс (по желанию) → сценарий с правками →
картинки с перегенерацией → озвучка → готовое видео в чат.

## Создание бота

1. В Telegram откройте **@BotFather** → команда `/newbot` → придумайте имя
   и username. BotFather выдаст **токен** вида `1234567:AA...`.
2. На сервере впишите токен в `.env`:

   ```bash
   cd ~/Amg
   nano .env
   # TELEGRAM_BOT_TOKEN=ваш_токен
   ```

3. (По желанию) чтобы ботом могли пользоваться только вы: узнайте свой id у
   **@userinfobot** и впишите его в `TELEGRAM_ALLOWED_CHAT_ID`. Пусто — бот
   открыт всем, кто его найдёт.

## Запуск

Разово, для проверки (остановится при закрытии SSH):

```bash
cd ~/Amg
npm run bot
```

Постоянно, через systemd (переживает перезагрузки сервера):

```bash
cp ~/Amg/scripts/amg-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now amg-bot
```

Если проект лежит не в `/root/Amg` — поправьте `WorkingDirectory` в
файле сервиса перед копированием.

Полезные команды:

```bash
systemctl status amg-bot          # работает ли
journalctl -u amg-bot -f          # живой лог
systemctl restart amg-bot         # перезапуск
```

Автодеплой (`scripts/auto-deploy.sh`) сам перезапускает бота после
обновления кода, если сервис установлен.

## Профили продуктов

Профиль хранит **роль/описание продукта** и **разобранный стиль референса**,
чтобы не присылать их для каждого ролика. Разбор референс-видео — самая
долгая часть, и с профилем он делается один раз. Профилей может быть
сколько угодно: по одному на продукт или площадку.

```
/newprofile — создать: имя → роль и контекст → ссылка на референс (или /skip)
/profiles   — список, кнопка ▶️ начинает ролик, 🗑 удаляет
```

После этого `/new` предлагает выбрать профиль, и бот спрашивает только
**тему конкретного ролика** — роль и стиль уже взяты из профиля. Если тема
не важна, отправьте `/skip`, и сценарист придумает сам.

Профили привязаны к чату и не пропадают при `/cancel`, перезапуске бота и
обновлениях кода.

## Как пользоваться

1. `/new` — если профили есть, бот предложит выбрать один (или «Без
   профиля»). Без профилей спросит бриф: что за продукт, для кого, посыл.
2. Референс: пришлите ссылку на Google Drive с видео (доступ «всем, у кого
   есть ссылка») — бот скачает его, нарежет кадры и выведет описание стиля,
   которое будет добавлено в промпты картинок. Либо `/skip`.
3. Сценарий: бот покажет заголовок и сцены. Кнопки «✅ Ок, рисуем» /
   «✏️ Правки» — во втором случае напишите замечания, бот перепишет.
4. Модель картинок: перед отрисовкой бот предложит выбор — Nano Banana
   (проверенная), Nano Banana 2 (детальнее), Nano Banana 2 Lite (быстрее и
   дешевле), Nano Banana Pro (максимум качества, ~$0.09/картинка), GPT Image 2 (другая манера, от OpenAI). Прошлый выбор помечен
   звёздочкой и запоминается между роликами. У каждой модели свой формат
   запроса к Kie.ai — это учтено в `src/pipeline/imageModels.ts`; слаги
   моделей, кроме проверенной Nano Banana, взяты из документации Kie.ai, и
   если какой-то устарел, ошибка придёт в чат читаемым текстом — просто
   выберите другую модель.
5. Картинки: бот рисует сцены по очереди и присылает каждую. В конце —
   «✅ Собирать видео» / «🔄 Перегенерировать сцену» (спросит номер).
6. Озвучка и сборка: бот проговаривает прогресс и присылает готовый
   `video.mp4` в чат.

`/cancel` — сбросить диалог на любом шаге.

`/deploy` — обновить бота с GitHub немедленно, не дожидаясь планового
автодеплоя (тот проверяет обновления раз в 5 минут). Если были изменения,
бот перезапустится и на минуту пропадёт. Какая версия кода сейчас работает —
видно в `/start`.

## Подбор голоса: /voice

`/voice` — показать текущий голос. `/voice <voice_id>` — сменить и сразу
послушать пробную фразу, которую бот пришлёт голосовым сообщением. Выбранный
голос сохраняется и используется для всех последующих роликов (переживает
`/new` и `/cancel`).

**Kie.ai принимает только ID голоса, не имя.** В их документации пример
показывает имя (`"voice": "Rachel"`), но допустимые значения — ID, и с именем
задача падает с `internal error, please try again later`. Имена классических
голосов ElevenLabs (Rachel, Bella, Antoni, Josh, Adam) подставляются в ID
автоматически, включая значение из `.env` — так что старая настройка
`KIE_TTS_VOICE=Rachel` не ломает озвучку. Для всех остальных голосов нужен
ID; если бот скажет, что значение не похоже на ID, а вы уверены — есть
`/voiceforce <значение>` в обход проверки.

Где брать ID: библиотека голосов ElevenLabs (в адресе страницы голоса или в
его настройках) либо кабинет Kie.ai. Для русской озвучки берите голос с
поддержкой multilingual — модель по умолчанию
(`elevenlabs/text-to-speech-multilingual-v2`) читает по-русски, но
англоязычные голоса делают это с акцентом.

## Клонирование голоса из своих роликов: /clone

Если хочется, чтобы ролики звучали тем же голосом, что в референсах, бот
сделает клон целиком сам — без ручной работы в веб-интерфейсе:

1. `/clone` → спросит имя голоса (например «Шамиль»)
2. Присылайте материал — двумя способами, можно вперемешку и по одному:
   - **файлом прямо в чат**: видео, аудио, голосовое или документ. Telegram
     отдаёт боту файлы до 20 МБ — для звуковой дорожки этого хватает с
     запасом;
   - **ссылкой на Google Drive** (доступ «всем, у кого есть ссылка») — так
     проходят и большие видео на сотню мегабайт.

   После каждого файла бот отвечает, сколько секунд принято и сколько
   накопилось всего.
3. `/done` — бот склеивает сэмплы, убирает музыку через Voice Isolator,
   присылает очищенный звук послушать, создаёт клон, сразу выбирает его для
   роликов и произносит пробную фразу.

Всё это делает сервер: **в веб-интерфейс ElevenLabs заходить не нужно.**
Сэмплы копятся на диске и переживают перезапуск бота; `/cancel` их удаляет.

**Сколько материала нужно.** ElevenLabs рекомендует минимум минуту чистой
речи, лучше две-три. Бот считает суммарную длительность и предупредит, если
её мало: из 20–30 секунд клон выйдет узнаваемым, но с неровной интонацией.

Требуется `ELEVENLABS_API_KEY` (через Kie.ai клонирование недоступно) и
тариф Starter или выше — у Creator есть. Про эти ограничения бот сообщает
понятным текстом.

**Как проверить, какой голос активен.** `/voice` без аргументов показывает
не только ID, но и имя голоса в ElevenLabs — по нему видно, выбран ли,
например, «Шамиль» или «Шамиль2». `/voices` выводит весь список, где активный
помечен ▶️.

Не понравился результат — `/clone` с другими исходниками, вернуться к
прежнему голосу — `/voice <id>`.

**Про права:** клонировать чужой голос без разрешения нельзя, и ElevenLabs
требует это подтвердить. Если голос в референсе сгенерирован нейросетью,
уточните у агентства, какой именно — возможно, это стандартный голос
библиотеки, и его достаточно взять по ID через `/voice`, без клонирования.

## Если озвучка падает: /diag и /model

`/diag` — перебирает известные модели TTS с текущим голосом, коротким
запросом, и показывает по каждой, что ответил Kie.ai (успех или точная
причина отказа). Первую рабочую сохраняет автоматически, после чего можно
вернуться к сборке кнопкой «Повторить». Проверка занимает до 2 минут на
модель.

Это нужно потому, что слаги моделей у Kie.ai меняются, и какие доступны на
конкретном аккаунте — надёжнее выяснить запросом, чем по документации.

`/model` — показать текущую модель озвучки, `/model <слаг>` — задать вручную
(если нашли актуальный список в кабинете Kie.ai). Выбор, как и голос,
сохраняется между роликами.

Если `/diag` показал, что не работает ни одна модель Kie.ai, он сам проверит
резервный путь (см. ниже) и переключится на него, когда тот доступен.

## Резервная озвучка: /tts

Прокси Kie.ai для моделей ElevenLabs периодически отдаёт свои внутренние
ошибки (`internal error`, `Server exception … contact customer service`) —
при том, что картинки тем же ключом генерируются нормально. Чтобы это не
блокировало выпуск роликов, озвучку можно вести напрямую через ElevenLabs.

```
/tts            — показать текущего провайдера
/tts kie        — озвучка через Kie.ai (по умолчанию, один ключ на всё)
/tts elevenlabs — напрямую, нужен свой ключ ElevenLabs
```

Для прямого пути добавьте в `.env` на сервере:

```
ELEVENLABS_API_KEY=ваш_ключ_с_elevenlabs.io
```

и перезапустите бота (`/deploy` или `systemctl restart amg-bot`). Голоса
задаются так же (`/voice`), ID и имена работают одинаково для обоих путей.

Два ограничения бесплатного тарифа ElevenLabs, о которые легко споткнуться:

- **Права у ключа.** В настройках ключа (elevenlabs.io → Settings → API
  Keys) нужны разрешения `text_to_speech` — для самой озвучки, и
  `voices_read` — чтобы работала команда `/voices`. Без них приходит 401
  `missing the permission`. ID голоса можно узнать и без всяких прав: на
  сайте в разделе Voices / My Voices откройте голос — там показан Voice ID.
- **Только базовые голоса.** Библиотечные и клонированные голоса через API
  бесплатным аккаунтам недоступны (402 `paid_plan_required`) — включая
  классическую Rachel. Команда **`/voices`** покажет голоса, доступные
  именно вашему ключу, с отметкой, какие из них базовые (premade) —
  выбирайте из них.

Оба случая бот распознаёт и объясняет словами, а не сырым JSON.

Выбор провайдера сохраняется между роликами. Когда Kie.ai починит свою
сторону, вернуться можно командой `/tts kie`.

## Что нужно знать

- **Одна генерация за раз.** Пока собирается ролик, новые запросы ждут.
- **Состояние хранится** в `data/bot-state.json` — перезапуск бота не
  стирает текущий диалог.
- **Длина ролика**: до 15 сцен, но не дольше 60 секунд — лимиты задаются в
  `.env` (`MAX_SCENES`, `MAX_VIDEO_SECONDS`). Сценарист получает бюджет слов
  на сцену: чем больше сцен, тем короче реплики. Если озвучка всё же вышла
  длиннее, бот сжимает паузы между сценами, а когда и этого мало — пишет об
  этом и предлагает сократить текст через «✏️ Правки».
- **Звуки переходов** играют на каждом стыке сцен (`public/sfx`) — щелчок,
  хлопок, снап и удар под смятие. Все резкие: атака в единицы миллисекунд,
  спад в десятки, никаких плавных наплывов. Соседние стыки не получают один и
  тот же звук. Сгенерированы программно (`scripts/build-sfx.mjs`), не
  лицензионные.
- **Хук в первой сцене обязателен.** Сценарист получает жёсткие правила
  (никаких «привет» и «в этом видео», до 12 слов озвучки, до 5 слов подписи),
  а после генерации бот сам проверяет начало и, если оно слабое, просит
  переписать только первую сцену — тогда в чат приходит строка
  «🪝 Хук переписал: …» с причиной. В списке сцен хук помечен 🪝.
  В кадре он подан отдельно: карточка видна с первого кадра и доезжает
  упругим наездом, подпись приходит крупнее, а в начале ролика играет
  подъём с ударом.
- **Фоновая музыка**: команда `/music` — 7 готовых настроений (бодрый бит,
  лоу-фай, игривый, технологичный, кинематографичный, восточный, фанк).
  Нажимаете нужное — Kie.ai генерирует инструментальный трек (1-2 минуты,
  тратит кредиты) и добавляет в библиотеку. Для каждого ролика берётся
  случайный трек из библиотеки, громкость 12% под озвучкой. Свои файлы тоже
  можно класть в `assets/music/` вручную. Пустая библиотека — ролики без
  фона.
- **Ролик информативный, а не рекламный.** Сценарист получает жёсткую
  структуру: хук, затем польза по теме (приёмы, порядок действий, типичные
  ошибки, названия инструментов), и только последняя сцена — призыв к
  действию. Если реклама всё же попала в середину, бот сам просит переписать
  и сообщает в чат: «✏️ Переписал: реклама попала в середину ролика…».
- **Середина — приёмы, а не перечисление сервисов.** Если сцены выглядят как
  список названий («Midjourney сделает раскадровку», «Suno напишет музыку»)
  или содержат пустой восторг, штампы и непроверяемые цифры («до 90%
  бюджета», «за 15 минут»), бот просит переписать и говорит, что именно не
  понравилось. Оптимально 5-8 сцен: на 15 сценах в реплику влезает четыре
  слова, и польза в них не помещается.
- **Ссылки в озвучку не попадают.** Веб-поиск заставляет модель дописывать
  источники прямо в текст — бот вырезает их, иначе синтезатор читает адрес
  сайта вслух.
- **Актуальность тем**: к первому запросу сценария подключается веб-поиск,
  поэтому ролик может опираться на свежие модели и приёмы, а не только на
  знания модели. Если поиск не сработал, бот об этом предупредит — значит
  тему стоит перепроверить. Отключается `SCRIPT_WEB_SEARCH=0` в `.env`.
- **Текста на картинках нет.** Подпись сцены рисует Remotion чистым шрифтом
  под карточкой; раньше ту же фразу дублировала сама картинка, и кадр читался
  дважды. Теперь в промпте стоит запрет на любые надписи, а подпись в промпт
  не попадает вовсе — иначе модель норовит её нарисовать.
- **Голос**: `/voice` показывает не только ID, но и имя в ElevenLabs,
  провайдера и параметры похожести — по нему видно, тот ли клон активен.
  Клонированный голос звучит только при прямом провайдере: перед озвучкой бот
  предупредит, если выбран клон, а провайдер остался `kie` (Kie.ai ходит в
  ElevenLabs со своего аккаунта и вашего голоса не видит) — переключение
  `/tts elevenlabs`.
- **Лимит Telegram на отправку видео ботом — 50 МБ.** Наши ролики обычно
  5–15 МБ, но если сделаете очень длинный и упрётесь в лимит — заберите
  файл с сервера напрямую: `scp root@ip:~/Amg/out/video.mp4 .`
- **Референс качается в обход Telegram** (по ссылке с Google Drive), поэтому
  лимит на большие файлы не мешает — 100 МБ тоже пройдут.
- **Расходы не ограничены**: каждый ролик — реальные списания у OpenRouter и
  Kie.ai (сценарий ≈ центы, картинки ≈ $0.04–0.12 за сцену, озвучка по
  тарифу Kie). Лимитов в боте нет — следите за балансом сами.

## Если что-то пошло не так

Бот присылает текст ошибки прямо в чат и предлагает `/new`. Подробности —
в логе: `journalctl -u amg-bot -n 50`. Частые причины — те же, что у
CLI-пайплайна, см. раздел «Если что-то пошло не так» в `docs/SERVER.md`.
