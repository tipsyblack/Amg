# Amg — пайплайн автогенерации коротких видео

Автоматическая сборка коротких вертикальных роликов (Instagram Reels, YouTube
Shorts, TikTok, VK Клипы) под несколько продуктов сразу: сценарий генерирует
**OpenRouter**, озвучку и иллюстрации — **Kie.ai** (модели ElevenLabs и
Nano Banana под одним ключом), финальный ролик собирает **Remotion** (видео
как React-компоненты).

## Как это работает

1. `npm run generate -- "бриф о продукте и посыле видео"` —
   - OpenRouter (модель Gemini Flash) генерирует сценарий: заголовок + сцены
     (текст на экране + текст озвучки);
   - Kie.ai озвучивает текст каждой сцены моделью ElevenLabs и сохраняет
     `.mp3` в `public/audio/`;
   - Kie.ai генерирует иллюстрацию для каждой сцены (по умолчанию
     Nano Banana Edit) и сохраняет `.png` в `public/images/` — в каждый
     запрос передаётся эталонное изображение персонажа и картинка предыдущей
     сцены, чтобы персонаж и стиль держались из сцены в сцену;
   - длительность каждой сцены рассчитывается по реальной длине аудио и
     записывается вместе со сценарием в `data/video-data.json`.
2. `npm run render` — Remotion рендерит `data/video-data.json` в
   `out/video.mp4`.
3. `npm run preview` — открывает Remotion Studio для визуальной проверки/
   правки шаблона в браузере.

## Про повторение стиля готового видео

Готового сервиса «загрузи видео — получи точную копию дизайна и анимации»
не существует: переходы, тайминг, шрифты и раскадровку нужно один раз
воссоздать вручную (или получить у агентства исходники монтажа) в виде
Remotion-шаблона. Дальше шаблон переиспользуется программно для любого
количества роликов — в этом и есть автоматизация.

По присланному референсу воссоздан "каркас" ролика в `src/remotion/Scene.tsx`:
белый фон, скруглённая карточка в толстой чёрной рамке, под ней — жирная
чёрная капслок-подпись узким гротеском (Oswald 700, как в референсе).
Анимация: медленный наплыв на картинку (зум и панорама в разные стороны),
появление карточки одним из вариантов (проявление, наложение поверх
предыдущей, выезд, зум-удар, покачивание) и уход другим (смятие с перекосом,
сжатие, увод вверх), звук на каждом стыке. Набор перебирается по номеру сцены,
поэтому подряд идущие сцены двигаются по-разному, а рендер остаётся
повторяемым — см. `src/remotion/transitions.ts`.

Звуки на стыках — резкие: щелчок, хлопок, снап и удар (атака в единицы
миллисекунд, спад в десятки). Они синтезируются `node scripts/build-sfx.mjs`
через ffmpeg, лежат в `public/sfx` в формате wav и выровнены по громкости до
~-20 dB RMS, чтобы один стык не звучал ударом, а другой еле слышно. Соседние
стыки никогда не получают один и тот же звук.

Первая сцена — **хук**, и подача у неё отдельная: карточка видна с первого
кадра (он же обложка в ленте) и доезжает упругим наездом, подпись приходит
крупнее и садится в размер, а в самом начале играет подъём с ударом
(`public/sfx/hook.wav`). Сам текст хука пишется по жёстким правилам и
проверяется автоматически — см. «Хук» ниже.

Картинка внутри карточки генерируется через Kie.ai
(`src/pipeline/generateImage.ts`) по описанию стиля (`STYLE_PROMPT`),
выведенному из кадров референса: плоская векторная иллюстрация, толстый
чёрный контур, приглушённая пастельная палитра. Текста в кадре быть не должно
(`NO_TEXT_RULE`): подпись рисует Remotion чистым шрифтом, и надпись внутри
картинки дублировала бы её — тем более что кириллицу картиночные модели рисуют
с ошибками. По той же причине подпись сцены не попадает в промпт: увидев
готовую фразу, модель норовит её нарисовать, поэтому сцена описывается только
текстом озвучки.

Главный персонаж — фирменный маскот "Pro Neiro", джин **Шамиль (Шама)**.
Его эталонное изображение лежит в `assets/characters/shamil.png` и
прикладывается к каждому запросу генерации картинки как референс внешности
(лицо, причёска, одежда, цвета), поверх текстового описания в
`STYLE_PROMPT` — так модели проще держать персонажа узнаваемым между сценами.

Kie.ai принимает входные картинки только по публичной ссылке, поэтому эталон
передаётся ссылкой на файл в этом репозитории (raw.githubusercontent.com).
Если сделаете репозиторий приватным — выложите картинку в другое публичное
место и укажите адрес в `CHARACTER_REFERENCE_URL`.

Важная оговорка: это приближение через промпт + референс-изображение, не
точная копия. Консистентность персонажа не гарантирована на 100% и зависит
от возможностей image-модели. Если результат расходится с ожиданиями —
`STYLE_PROMPT` в `generateImage.ts` стоит донастраивать по факту (например,
уточнить типовые ракурсы/позы Шамиля), а `assets/characters/shamil.png`
можно заменить на более "чистый" референс без логотипа лампы, если он
будет мешать генерации.

## Хук

Первые 1-2 секунды решают, досмотрят ролик или пролистнут, поэтому хук в
первой сцене обязателен и не отдаётся на волю модели.

- **В промпте** (`buildSystemPrompt` в `src/pipeline/generateScript.ts`)
  первая сцена описана отдельным блоком: запрещены приветствия,
  представления и «в этом видео», озвучка — не больше 12 слов, подпись — до
  5 слов, плюс список рабочих приёмов (боль зрителя, неожиданное
  утверждение, вопрос в лоб, обещание результата).
- **После генерации** сценарий проходит проверку `hookProblem()`: слабое
  начало ловится регуляркой (модель про запрет иногда забывает), считаются
  слова в озвучке и подписи. Если хук не годится, `generateScriptWithHook()`
  делает одну целевую правку — просит переписать только первую сцену,
  остальные оставить дословно. Причина правки уходит в лог CLI и в чат бота
  («🪝 Хук переписал: …»), так что видно, что именно не понравилось.
- **Вторая попытка не зацикливается**: если и переписанный хук слаб, берётся
  тот сценарий, что есть — пустой результат хуже слабого.
- **Подача** хука усилена в кадре и в звуке (см. раздел про стиль выше).

## Голос

Озвучка идёт моделями ElevenLabs — либо через прокси Kie.ai (по умолчанию),
либо напрямую (`/tts elevenlabs`, нужен `ELEVENLABS_API_KEY`).

Параметры похожести задаются в `.env` (`TTS_*`) и одинаковы для обоих путей:
`similarity_boost` 0.9 держит тембр исходной записи, `style` 0 не даёт модели
«играть» и уводить от оригинала, `stability` 0.4 оставляет живую интонацию, а
`use_speaker_boost` (только прямой путь) добавляет сходства с оригинальным
голосом.

**Клонированный голос работает только напрямую.** Клон живёт в вашем аккаунте
ElevenLabs, а Kie.ai обращается к ElevenLabs со своего — вашего голоса он не
видит, и ролик будет озвучен другим. Бот проверяет это сочетание сам
(`cloneViaProxyWarning`): если выбран не базовый голос, а провайдер остался
`kie`, перед озвучкой придёт предупреждение с подсказкой `/tts elevenlabs`.
Какой именно голос активен, показывает `/voice` — он спрашивает имя у
ElevenLabs, так что видно, тот ли это клон.

Про качество самого клона: мгновенное клонирование (Instant Voice Cloning)
делает похожий голос от минуты чистой речи, а на 20-30 секундах с музыкой на
фоне получается лишь отдалённое сходство. Поэтому в боте есть `/clone`: он
вытаскивает дорожку из ваших роликов, убирает фон через ElevenLabs Voice
Isolator и склеивает несколько фрагментов в один сэмпл.

## Требования для рендера

`npm run render` при первом запуске скачивает headless Chrome (через
`@remotion/renderer`). В песочницах с ограниченным egress-доступом нужно
разрешить хост `remotion.media`; в обычном окружении/CI это происходит
автоматически.

## Установка

```bash
npm install
cp .env.example .env
# заполнить .env: OPENROUTER_API_KEY и KIE_API_KEY
```

Для установки на выделенный сервер (Ubuntu/Debian) есть готовый скрипт и
пошаговая инструкция: **[docs/SERVER.md](docs/SERVER.md)**.

```bash
sudo bash scripts/setup-server.sh
```

## Телеграм-бот

Ролики можно собирать прямо из Telegram: бриф → референс по ссылке с
Google Drive → согласование сценария (с правками) → согласование картинок
(с перегенерацией отдельных сцен) → озвучка → готовое видео в чат.
Роль и стиль референса можно сохранить в **профиль** (`/newprofile`) — тогда
для очередного ролика достаточно выбрать профиль и назвать тему.
Настройка: **[docs/BOT.md](docs/BOT.md)**, запуск — `npm run bot`.

```
  BOT.md            # телеграм-бот: настройка и использование

  auto-deploy.sh    # подтягивание обновлений из GitHub на сервер

  test-image-models.mjs # форматы запросов моделей картинок
  build-font-data.mjs # пересборка вшитого шрифта из public/fonts
  build-sfx.mjs     # синтез звуков стыков и хука (ffmpeg, без лицензий)

  remotion/        # шаблон видео (Remotion)

    VideoComposition.tsx  # раскладка сцен по таймлайну + фоновая музыка
    Scene.tsx       # стиль и анимация одной сцены (карточка + подпись)
    transitions.ts  # варианты появления/ухода сцен и звуки переходов
    font.ts         # шрифт подписей (Oswald 700, вшит в код)
    fontData.ts     # шрифт в base64 (генерируется скриптом)
  pipeline/         # генерация контента
    config.ts        # чтение .env
    generateScript.ts # запрос к OpenRouter (сценарий, цикл правок)
    kie.ts           # клиент Kie.ai: создание задачи, ожидание, скачивание
    generateImage.ts  # иллюстрация сцены через Kie.ai, STYLE_PROMPT
    generateVoiceover.ts # озвучка через Kie.ai (модель ElevenLabs)
    generateMusic.ts # фоновая музыка через Kie.ai (Suno), 7 пресетов
    voiceClone.ts   # очистка от музыки и клонирование голоса (ElevenLabs)
    audioDuration.ts # длительность сгенерированного аудио
    assets.ts        # пошаговые операции: аудио/картинка сцены, музыка
    buildVideoData.ts # сборка data/video-data.json
    index.ts          # CLI-точка входа (npm run generate)
  bot/              # телеграм-бот (npm run bot)
    index.ts         # диалог, согласования, очередь
    state.ts         # состояние диалога и профили (data/bot-state.json)
    drive.ts         # скачивание с Google Drive (подтверждение, диагностика доступа)
    referenceStyle.ts # кадры из референса -> описание стиля (vision)
    extractAudio.ts  # дорожка из видео и склейка сэмплов для клонирования
  types.ts          # схема данных видео (zod), общая для pipeline и Remotion
public/fonts/       # шрифт подписей, лежит в репозитории (лицензия OFL)
public/sfx/         # звуки стыков и хука (scripts/build-sfx.mjs, в репозитории)
public/audio/       # аудио-дорожки сцен (генерируются, в git не попадают)
public/images/      # иллюстрации сцен (генерируются, в git не попадают)
public/music/       # трек текущего ролика (копируется из assets/music)
data/               # video-data.json, bot-state.json (в git не попадают)
```

## Проверки

```bash
npm run typecheck   # типы
npm run test:kie    # клиент Kie.ai на локальном моке (без реальных запросов)
npm run test:bot    # разбор команд бота (в т.ч. скопированных с форматированием)
npm run test:elevenlabs # список голосов и расшифровка ошибок ElevenLabs
npm run test:images # форматы запросов моделей генерации картинок
npm run test:profiles # профили продуктов и хранилище состояния бота
npm run test:timing # лимит длины ролика и набор вариантов анимации
npm run test:music  # генерация музыки на моке и библиотека треков
npm run test:clone  # извлечение/склейка дорожек и клонирование голоса
npm run test:drive  # скачивание с Google Drive и диагностика закрытого доступа
npm run test:hook   # проверка хука и переписывание слабого начала
```

`npm run test:kie` поднимает фальшивый сервер Kie.ai и проверяет асинхронный
цикл (создание задачи → опрос статуса → скачивание результата) и обработку
ошибок: отказ задачи, пустой результат, таймаут. Реальные запросы к API не
уходят, кредиты не тратятся.

## Форматы под площадки

По умолчанию — вертикальный формат 1080×1920 (Reels/Shorts/TikTok/VK
Клипы). Меняется через `VIDEO_WIDTH`/`VIDEO_HEIGHT` в `.env`; для
горизонтального YouTube-формата можно рендерить тот же шаблон повторно с
1920×1080 — раскладка сцены рассчитана на `AbsoluteFill` и подстроится под
любые пропорции без правок кода.

## Заметки по инструментам

- **OpenRouter** (сценарий): модель задаётся через `OPENROUTER_MODEL` (по
  умолчанию `google/gemini-2.5-flash`). Список ID моделей может меняться,
  актуальный — на openrouter.ai/models.
- **Резервная озвучка**: прокси Kie.ai для моделей ElevenLabs бывает
  нестабилен (отдаёт свои `internal error` при работающей генерации картинок
  тем же ключом). На этот случай есть прямой путь к ElevenLabs — добавьте
  `ELEVENLABS_API_KEY` в `.env` и переключитесь командой `/tts elevenlabs`
  в боте (или `TTS_PROVIDER=elevenlabs`).
- **Kie.ai** (озвучка + картинки): один ключ `KIE_API_KEY` на оба сервиса.
  API асинхронный — задача создаётся, потом опрашивается до готовности; вся
  эта логика в `src/pipeline/kie.ts`. Модели задаются через `KIE_TTS_MODEL`
  и `KIE_IMAGE_MODEL`, голос — через `KIE_TTS_VOICE`. Названия моделей и
  доступные голоса сверяйте в кабинете Kie.ai: они меняются.
- Для картинок нужна модель, принимающая входные изображения (image-to-image,
  по умолчанию `google/nano-banana-edit`) — иначе эталон персонажа не будет
  учитываться и Шамиль перестанет быть похожим на себя.
- Права на дизайн/анимацию из заказанных у агентства видео стоит уточнить
  по договору, прежде чем воспроизводить их 1:1.
